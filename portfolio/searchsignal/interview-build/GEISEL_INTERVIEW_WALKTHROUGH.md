# SearchSignal — Geisel Interview Walkthrough

This guide is the five-minute review path for a hiring conversation. SearchSignal is an independent portfolio project and does not imply access to Dartmouth internal systems.

## Walkthrough

1. Open **Geisel Interview Mode** and explain the operating loop: inspect → prioritize → change safely → support → measure.
2. Run the **Live URL Auditor** on a public Geisel page and open one evidence-backed finding.
3. Open **Site Intelligence** and run a small same-origin sample. Show page inventory, architecture signals, document discovery/checks, JSON evidence export, and the redirect-chain validator.
4. Open **Priority Roadmap**. Change one 1–5 input to show that the sequence is explainable rather than a black-box ranking.
5. Open **WordPress Support** and explain what can be handled at page/editor level versus what should be escalated to architecture/server owners.
6. Open **Training Center** to show how a repeated support issue becomes reusable editor guidance.
7. Open **Analytics & AI Visibility** and explain what would be measured after implementation.
8. Open **Requirements Coverage** and GitHub to show what is working, connector-ready, learning-only, and independently built.

## Accuracy boundary

The Geisel case study uses public pages and clearly labeled demonstration inputs. It does not claim access to Geisel Search Console, Analytics, production WordPress administration, staffing data, application volume, or internal priorities.

The richer published SearchSignal v2 remains the target production demo. This local interview build adds the Geisel-specific guided workflow and visual presentation. It should not be described as replacing v2 until the current Floot source is exported, reconciled, and the interview features are ported into that live build.

## What this demonstrates

A reviewer can see the working method instead of being asked to infer it from a resume: diagnose an observable problem, explain the evidence, decide what matters first, respect change boundaries, help nontechnical editors, and measure the result.
