# Forge Suite — Build + Upgrade History

1. Established Forge as a local-first shared runtime instead of separate duplicated app stacks.
2. Built Forge Base for durable workspace layout, model/tool caching, recovery, backups, manifests, and offline/fallback routes.
3. Added the shared Forge Core for model routing, tool execution, storage, media services, FFmpeg assembly, Blender integration, and hardware-aware fallbacks.
4. Built Elias as the independent general assistant, then added Evidence Auditor as an optional evidence workspace rather than making evidence access mandatory.
5. Evolved Evidence Auditor from the legacy Streamlit implementation into Evidence Cloud, source-grounded review, chronology/contradiction analysis, and defense-style PDF packet generation.
6. Built MedForge around image/mechanism teaching, generated educational visuals, and shared Blender 3D mechanism rendering.
7. Evolved GrimForge from cinematic prototype to Simple/Pro and then to the current 3D / 2.5D / 2D full-episode pipeline with continuity, narration, captions, FFmpeg assembly, and explicit engine boundaries.
8. Added Forge Learn as a synchronized teaching layer that explains actual production capabilities, dependencies, failure modes, and data flow.
9. Added Forge Builder for local-first app planning, scaffolding, snapshots, browser preview, and static QA gates.
10. v0.5.6 recovery restored batch Evidence workflows, one-click packet creation, GrimForge engine preflight/fallback handling, MedForge end-to-end teaching packages, and six-product design parity.
11. Target-PC acceptance is now being executed separately: Windows preservation, narrator quality, Blender visual quality, ComfyUI visual quality, full GrimForge episode assembly, and CareFlow real-participant research.
12. Current evidence rule: implemented, fixture-tested, live-engine-tested, and visually/user-reviewed are separate states; a passing fixture or website smoke test never substitutes for a real acceptance run.
